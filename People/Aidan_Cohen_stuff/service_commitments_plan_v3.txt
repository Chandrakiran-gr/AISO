--- Deliverable 3: Website File Implementation (NEW) ---
PURPOSE: We implement an llm.txt file (and other relevant files) directly on
the client's website as part of the technical setup. This embeds the client
into AI search pathways at the source level.

Default path — we request website access:
  We ask for backend access to the client's website to implement and maintain
  the necessary files directly. This is the preferred approach because it lets
  us iterate on the llm.txt, add additional files over time, and make updates
  without going back and forth with the client.

Opt-out clause — if client doesn't want to give access:
  If the client prefers not to grant access, we deliver the file(s) directly
  and assist them in getting it live on their site.

Suggested copy for the doc:
  Name: "Website File Implementation"
  Body: "To establish your presence in AI search at the technical level, we'll
  implement the necessary files directly on your website. We'll request backend
  access to handle this — and keep it updated — ourselves. If you'd prefer not
  to share access, we'll deliver the files to you directly and walk you through
  getting them live."

Notes:
  - Lead with the access-first path — make it sound like the normal thing
  - The opt-out should feel like an accommodation, not the default
  - Don't use the term "llm.txt" in the client-facing doc — just "the necessary
    files" or "technical files". Keeps it clean and non-intimidating.
  - This also covers future files beyond llm.txt — the language is intentionally
    broad enough to include anything else added to the site down the line

--- Deliverable 4: Written Observations (NEW) ---
PURPOSE: Commit to writing the client something useful without specifying
exactly what. Should feel like expert attention, not a report format.

Language goal: "I'm going to write you something worth reading" — open-ended
on content, closed on the fact that it will happen.

Suggested copy for the doc:
  Name: "Written Observations"
  Body: "Alongside your charts, we'll share our written take — what we're
  seeing in your space, what stands out, and anything we think is worth
  your attention as we get started."

Notes on this deliverable:
  - Do NOT specify length, format, or exact content
  - Do NOT use words like "report", "analysis", "summary" — too formal/specific
  - "Our written take" or "written observations" is the right register:
    implies expert attention, doesn't promise a deliverable structure
  - It should feel like something a smart person sent you, not a template
  - One paragraph description in the doc is enough — do not over-explain it

CHART IMPLEMENTATION NOTES
================================================================================

All charts: pure SVG inside HTML. No JS, no external libs. Must print cleanly.

Bar charts (SVG):
  - viewBox: "0 0 500 215"
  - Chart area: x=60 to x=395, y=20 to y=180 (height=160)
  - Bar width: 40px, 5 bars
  - Y-axis: left border line + rotated text label
  - X-axis: bottom border line
  - Gridlines: dashed, light gray (#ddd)
  - Value labels above each bar
  - Company name labels below x-axis
  - Legend: right of chart area

Line chart (SVG):
  - viewBox: "0 0 520 215"
  - Chart area: x=60 to x=370, y=20 to y=180 (height=160)
  - Y-axis: 0–40%, gridlines at 0/10/20/30/40%
  - X-axis: date labels + tick marks
  - Client line: stroke="#000", stroke-width=2.5, circle r=4
  - Competitor lines: stroke="#999"/"#aaa"/"#c0c0c0", stroke-width=1.5, r=3
  - Legend: right side, line samples + labels

Design rules:
  - Black and white only
  - Arial/Helvetica for labels and UI. Georgia for body copy.
  - No shadows, rounded corners, gradients
  - Do not look like AI output
  - All charts: title, both axis labels, units, legend

Writing rules (apply to ALL copy in the doc):
  - No em dashes (—) used as a stylistic crutch
  - No phrases like "cutting-edge", "leverage", "deliverables", "seamlessly",
    "streamlined", "robust", "in today's landscape", "tailored to your needs",
    "we are committed to", "our team", "ensuring that", "at the end of the day"
  - No bullet points in the body copy — prose only
  - Write like a person wrote it, not like a template was filled in
  - Short sentences. Plain words. If a normal person wouldn't say it out loud,
    cut it.
