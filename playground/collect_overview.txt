COLLECT OVERVIEW
===============

────────────────────────────────────────────────────────────────────────────────
WHAT collect.py DOES NOW (as it relates to the other stuff)
────────────────────────────────────────────────────────────────────────────────

Collect is the data-gathering script in full_stack. It runs after setup and before analysis.

PIPELINE CONTEXT
  • Setup (setup.py) — Run once per new client. Creates the client folder, runs an interactive chat to collect context (industry, products, geography), writes datafile.json, then uses AI to generate query_template_bank.csv and value_bank.csv. Writes config.json. Banks are not edited after setup.
  • Collect (collect.py) — Run whenever you want fresh data for that client. Reads the bank CSVs, builds questions, calls the search API, writes results. This document describes collect.
  • Analysis1 (analysis1.py) — Reads the aiso CSV output, extracts business names from responses, assigns links to focal/competitor/Unassigned, writes enriched CSV back.
  • Analysis2 (analysis2.py) — Reads the enriched CSV, finds addable domains, runs a browser+LLM agent to find register/list URLs, writes a separate addable-sites CSV.

CLIENT FOLDER STRUCTURE
  Each client has a folder under Integrated_ai/<slug>/ (e.g. Integrated_ai/sbaco/). That folder contains:
    • datafile.json — Client context from setup chat
    • query_template_bank.csv — Rows of search query strings with {placeholder} tokens (e.g. {city}, {service})
    • value_bank.csv — Rows of dict-like data; column names match placeholder names
    • config.json — slug, optional display_name
    • slug_aisodata0.csv, slug_aisodata1.csv, … — Versioned output from collect runs

BANK CSV FORMAT
  • Template bank: Header row; each cell value is a string with {placeholder} tokens. Example: "What are the best {service} in {city}?"
  • Value bank: Header row; column names must match placeholder names. Example row: service="kayak tours", city="Santa Barbara", ...
  • The question list is built by expanding the full template × value matrix: every template row × every value row, with placeholders filled in. The lib function build_queries_from_matrix(template_rows, value_rows) does this.

WHAT collect.py DOES (step by step)

  1. Resolve client folder
     • Input: Business folder path or slug (e.g. python full_stack/collect.py sbaco or python full_stack/collect.py Integrated_ai/sbaco)
     • If path: use it if it exists as a directory
     • If slug: normalize (lowercase, spaces/non-alphanumeric → underscore), resolve to Integrated_ai/<slug>/
     • Slug for output naming: from config.json in folder if present, else folder name
     • Require query_template_bank.csv and value_bank.csv in that folder. Exit with clear message if either missing (e.g. "Missing query_template_bank.csv in <path>")

  2. Load banks
     • read_csv_to_rows(client_folder / "query_template_bank.csv") → template_rows (list of dicts)
     • read_csv_to_rows(client_folder / "value_bank.csv") → value_rows (list of dicts)
     • Both must be non-empty; fail with clear message if empty or wrong structure

  3. Build question list
     • questions = build_queries_from_matrix(template_rows, value_rows)
     • Validate: len(questions) > 0, no "{" in any question (no unfilled placeholders)
     • Fail with clear message if validation fails

  4. Run webish for each question
     • For each question: call webish(query, mode="api") — returns a string response
     • On success: record (question, response, "")
     • On exception: record (question, "", str(exception)) — do NOT abort the run; continue to next question
     • Optional: print progress (e.g. loading bar)
     • The webish wrapper is call_webish(query) in full_stack/lib.py; it imports from webish.webish and calls webish(query, mode="api"). Requires OPENAI_API_KEY in env.

  5. Write versioned CSV
     • List files matching <slug>_aisodata*.csv in client folder
     • Parse N from each; next_n = max(parsed) + 1, or 0 if none exist
     • Write <client_folder>/<slug>_aisodata<next_n>.csv
     • Header: question, response, error
     • One row per question; same order as questions; error empty on success, error message on failure
     • UTF-8; do not overwrite existing files

RUNNING
  • From repo root (Integrated_ai): python full_stack/collect.py <path_or_slug>
  • Can also prompt for path/slug if no argument given
  • Env: OPENAI_API_KEY required (same as webish)

DEPENDENCIES
  • full_stack/lib.py: read_csv_to_rows, build_queries_from_matrix, call_webish
  • webish (existing module): webish(query, mode="api")
  • Repo root must be on Python path so "from full_stack.lib import ..." and webish import work

WHAT I WANT collect2.py TO DO
────────────────────────────────────────────────────────────────────────────────

The two main improvements I am paying for:

  1. Performance — Same behavior, significantly faster
     The program must do exactly what it does now, but a lot faster. Implementation approach is flexible. I have been experimenting with running multiple scripts in parallel, each calling the API concurrently.

  2. Multi-model support — Add Claude and Perplexity alongside ChatGPT
     Currently webish sends each question (from the slug data) to ChatGPT only. I want it to query Claude and Perplexity in the exact same way webish queries ChatGPT.
     Important: I do NOT want raw API calls to Perplexity and Claude. Webish configures the API and modifies the prompt so that responses mirror what ChatGPT returns in the browser. I want that same logic and behavior applied to Perplexity and Claude — the same prompt handling, the same response-shaping, the same integration pattern.
