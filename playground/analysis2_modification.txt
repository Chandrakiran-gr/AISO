analysis2_modification — Plan to add "integrateable" column (HOW_TO_PLAN compliant)

Take full_stack/analysis2.py as-is. Change the output so the CSV has exactly 3 columns. The first two columns stay (register URL, direct URL). The third column is "integrateable": the exact URL where someone can start adding the slug's business to that website — or blank if no such thing was found. A website is deemed integrateable only when an AI, after opening the site in a browser and clicking around, finds concrete evidence of "you can add your business here" and one concrete next step (e.g. a form, a "contact us to register" page, or a submission link). The value in the integrateable column is that specific link. If the AI cannot find anything like that, the row still appears but the integrateable cell is blank.


═══════════════════════════════════════════════════════════════════════════════
PRODUCT INTENT
═══════════════════════════════════════════════════════════════════════════════

What this is
  A modification of analysis2 so that the output CSV has 3 columns: the first two unchanged (register, direct), and a third column "integrateable" containing the exact URL where the slug's business can be started to be added — or blank.

Who it's for
  The same user who runs analysis2 (developer/analyst doing outbound-listing recommendations). They get a list where the third column tells them precisely where to go to add the business when the system could confirm it.

What problem it solves
  Today analysis2 outputs addable sites and a "feasible" flag from a brittle phrase scan. This change replaces that with: open each site in a browser, let an AI click around to find a real "add your business" entry point, and record that exact URL. So "integrateable" means: we have one concrete next step (a link) to start adding the business.

Outcome
  CSV with 3 columns. Rows for all addable domains; integrateable column is either the specific URL the AI found or blank. No prompts to the user; everything automatic.


═══════════════════════════════════════════════════════════════════════════════
HOW IT WORKS
═══════════════════════════════════════════════════════════════════════════════

High-level flow
  1. analysis2 runs as today through the point where we have addable_domains and domain_to_register_url (and domain_to_best_url, direct, etc.).
  2. For each addable domain, instead of (or in addition to) the current feasibility fetch:
     (a) Open a browser (automated: Playwright or Selenium) with the register URL (second column).
     (b) An AI agent gets the current page (DOM and/or screenshot), plus context: slug, business type from datafile.
     (c) The AI decides one of: FOUND — "I found a concrete place to add/register a business; here is the exact URL"; CLICK — "click this element" (selector or link href); GIVE_UP — "I see no way to add a business here."
     (d) If FOUND: store that URL in domain_to_integrateable[domain], close page, next domain.
     (e) If CLICK: perform the click in the browser, wait for load, go to (b) again (with a max step limit to avoid infinite loops).
     (f) If GIVE_UP: domain_to_integrateable[domain] = "" (blank), close page, next domain.
  3. Build output with exactly 3 columns: register, direct, integrateable. Write CSV as today (same path/filename).

Definition of "deemed integrateable" (must be in the plan)
  A website is deemed integrateable when the AI finds, by clicking around the live site, at least one concrete thing in "internet speak" that satisfies BOTH:
  (1) It is possible to add your business to this website (the slug's business type can be registered there).
  (2) Here is how you do it — one concrete next step. That can be: a form to submit a business, a "list your business" or "add your business" link, a "contact us to register your business" page, a directory signup URL, or any single link/URL that is the exact spot where someone would start that process.
  If the AI finds such a thing, the integrateable column gets that exact URL. If the AI cannot find anything like this after exploring (within step/time limits), the integrateable column is left blank. "Contact us to register your business" is explicitly valid as the concrete next step. The bar is: one concrete next step; it does not have to be a full plan or multiple steps.

Data flow
  • Input: unchanged (client folder, enriched aiso CSV, datafile for slug/business context).
  • New: browser automation + LLM with page content. Per domain: start URL = register URL; after agent run, integrateable = found URL or "".
  • Output: {slug}_aisodata{N}_new_addable.csv with 3 columns: register, direct, integrateable. Same file path as today.

Integrations
  • Reuse: all of analysis2 up to and including domain_to_register_url, addable_domains, direct_url.
  • New: browser automation library (Playwright preferred or Selenium); LLM API (OpenAI or existing project pattern) with vision or DOM text input; step limit and timeout per domain.

HOW TO USE / RUN

Prerequisites

Iteration
  • Re-run overwrites the CSV. To tune: adjust agent prompt, step limit, or timeout.


═══════════════════════════════════════════════════════════════════════════════
CONSIDERATIONS / GOTCHAS
═══════════════════════════════════════════════════════════════════════════════

  • Agent loops: Cap clicks per domain (e.g. 5–10 steps) and total time so one bad site doesn't hang the run.
  • Headless vs headed: For "AI clicks around," headed browser can help with JS-heavy sites; consider env flag (e.g. HEADED=1) for debugging.
  • Rate limits: LLM and browser; add short delays between domains if needed.
  • What to send the LLM: Screenshot + accessible text/links is often better than raw DOM. Specify in SPECIFICATIONS how page content is passed (e.g. screenshot + list of links and buttons).
  • Exact URL: On FOUND, the agent must return the current page URL or the href of the specific link that starts "add your business" — no guessing. That URL goes in integrateable.
  • Slug/business context: Pass datafile (industry, products_services, geography) or slug to the agent so it can judge "can this business be registered here."
