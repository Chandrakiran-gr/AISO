analysis1 — Full plan (HOW_TO_PLAN compliant)

Script: analysis1.py in full_stack. Next step after collect. Works for ANY slug that has had setup and collect run. User points the script at a slug (path or slug argument, same as collect). Uses the latest {slug}_aisodata{N}.csv for that slug.


═══════════════════════════════════════════════════════════════════════════════
PRODUCT INTENT
═══════════════════════════════════════════════════════════════════════════════

What this is
  analysis1.py enriches an existing aiso_data CSV by discovering which businesses (focal + competitors) are mentioned in each ChatGPT response and assigning every source link to the correct business column. The result is one column per business plus "Unassigned," so you can see where ChatGPT pulled each link from and for which business.

Who it's for
  The developer or analyst running the full_stack pipeline after collect. Same user who runs setup and collect.

What problem it solves
  Collect produces question/response/error rows but does not attribute links to businesses. Analysis answers: "For this response, which links were cited for the focal business vs competitors vs Unassigned?" — enabling comparison and quality checks without manual tagging. (Collect uses webish/API; "response" here means that model output, not necessarily ChatGPT brand.)

Outcome
  A single enriched CSV where every cited link is attributed to the right business column. Downstream: you can compare citation quality (focal vs competitors), spot missing or wrong attributions, and feed the same file into scoring or reporting without re-running collect.

HOW IT WORKS
═══════════════════════════════════════════════════════════════════════════════

High-level flow
  1. User runs analysis1 with a slug (or client folder path). Script resolves to client folder and slug (same pattern as collect).
  2. Script finds the latest {slug}_aisodata{N}.csv in that folder.
  3. First pass: scan every response in the CSV; use AI to detect business names mentioned. Build the list of "shown competitors" from the data (no external list). Focal business is the slug’s business (name from config or humanized slug).
  4. New columns: one for the focal business, one per discovered competitor, plus "Unassigned." Existing columns (question, response, error) are never modified — only new columns are added.
  5. Row by row: for each response, extract all markdown links [text](url); for each link, assign to the business column it’s related to (each business gets only the source(s) that mention it). Put each link in the correct column for that row. Multiple links per business in one row are stored in the same cell (e.g. newline- or comma-separated). Links not related to any business go in "Unassigned."
  6. Write the updated rows back to the same CSV file (in place).

Data flow
  • Input: client folder (from slug/path), latest aiso_data CSV.
  • In memory: rows as list of dicts; header = original headers + new business column names.
  • Output: same CSV path; same encoding (UTF-8); original columns unchanged; new columns appended.

Integrations
  • Reuses slug/client-folder resolution (same as collect — can share lib or duplicate pattern).
  • Reads/writes CSV only; no external APIs except any used for "AI to detect business names" and "assign link to business" (e.g. OpenAI if used).

Edge cases
  • Empty or error-only rows: no links extracted; new columns stay empty. No AI call needed for those rows.
  • Single response mentioning many businesses: AI must distinguish which link belongs to which business using surrounding context; same brand variants (e.g. "Wildside" vs "Wildside Nature Tours") collapse to one column.

HOW TO USE / RUN
═══════════════════════════════════════════════════════════════════════════════

Prerequisites
  • Python env with project deps (same as collect).
  • At least one {slug}_aisodata{N}.csv already exists for the slug (i.e. collect has been run).
  • OPENAI_API_KEY (or chosen AI provider key) set if using AI; script should check early and exit with clear message if missing (do not fail on first AI call).

Commands
  • Run from repo root so that full_stack.collect and imports resolve (same as collect):
    python full_stack/analysis1.py <slug_or_path>
  • Or:
    python full_stack/analysis1.py "Channel_Islands_Adventure_Company"
  • If no argument: prompt for "Business folder path or slug" (same as collect). If running from full_stack/, use python analysis1.py and ensure repo root is on sys.path (e.g. as in collect.py: _repo_root = Path(__file__).resolve().parent.parent; sys.path.insert(0, str(_repo_root))).

What runs
  • Resolves slug → client folder; finds latest aiso CSV; if that CSV was already analyzed, exits with message and does nothing. Otherwise discovers competitors, adds columns, fills link-by-business per row, writes once.

Iteration
  • Re-run on same slug is blocked: script detects already-analyzed CSV and exits with "Analysis is already completed for the aiso data in [slug]." No overwrite. To re-analyze, use a new aiso data file (e.g. run collect again to get a new N) or remove the analysis columns manually.

CONSIDERATIONS / GOTCHAS
═══════════════════════════════════════════════════════════════════════════════

  • Do not modify existing columns (question, response, error). Only append columns. Any tool that rewrites the CSV must preserve those three and their order.
  • Re-run is blocked: if the chosen aiso CSV already has analysis columns (header contains "Unassigned"), script does not overwrite; it exits with "Analysis is already completed for the aiso data in [slug]." No second run on the same file.

  • Same brand = same column: e.g. "Wildside" and "Wildside Nature Tours" map to one column; use name containment or normalization so one column per business.
  • Links that are not clearly tied to any business go in "Unassigned."
  • Rows with empty response (e.g. error-only rows): no links extracted; new columns get empty string for that row.
  • CSV quoting: when a cell contains multiple links (newlines or commas), ensure the cell is properly quoted so the CSV remains valid.
  • First run creates the new columns; re-run on the same file is not allowed (script exits with message).
  • AI used for "detect business names" and "assign link to business" — consider rate limits, cost, and idempotency (same input → same output if no API drift).
  • Large CSVs: processing is row-by-row with AI calls per row (or batched); progress logging or a row counter helps for big files.
  • Humanize: when deriving display names from slug/folder, convert snake_case to Title Case and replace underscores with spaces (e.g. channel_islands_adventure_company → "Channel Islands Adventure Company").
  • API key: at script start (before any AI step), check that OPENAI_API_KEY or the chosen provider key is set; if not, print a clear message (e.g. "OPENAI_API_KEY not set. See full_stack/.env.example.") and exit. Prevents failing mid-run on first AI call.

DECISIONS / GATHERED INFO
═══════════════════════════════════════════════════════════════════════════════

  • Competitors: derived only from the spreadsheet (scan all responses; add mentioned businesses to the list). No external competitor list.
  • Slug: any slug; script is pointed at slug (or path) like collect.
  • Output: modify the existing aiso_dataN file in place. Do not create a new file or change existing columns (question, response, error).
  • Focal business: the business being analyzed is the slug’s business. Column name for focal = from config "name" or "business_name" if present, else humanized slug (e.g. "Channel Islands Adventure Company"), else humanized folder name. When we discover businesses in the text, the one that matches that name/slug gets the focal column; the rest are competitors.
  • Detecting business names: use AI to flag when the script sees a business name in the response text (no rigid patterns like bold or "by X" only).
  • Link → column: One column per business; column header = that business’s brand name. Put each link in the column for the business it’s related to. If a response lists multiple businesses and each has its own source, each business gets only the source(s) that mention it in its column. Unassigned if the link isn’t related to any business.
  • Multiple links in one cell: when there are multiple links for one business in one row, store all of them in that cell (e.g. newline-separated inside the quoted CSV cell).
  • Column order: script chooses (e.g. focal, then competitors, then Unassigned); no strict preference.

  • AI — extract business names (Step 2.2.2):
    - Input: list of non-empty response strings (from 2.2.1). Optionally concatenate or send in batches to stay under model context limit.
    - Prompt shape: "From the following text(s), list every business or company name mentioned. Return only the names, one per line. Do not include the focal business name [focal_name] in the list." (Focal can be included and removed in 2.3.2; either way is fine.)
    - Output: flat list of strings (business names as mentioned). Duplicates and variants allowed; 2.3.1 will merge same brand.
    - Batching: if response_texts is large, send in chunks (e.g. up to N chars or M responses per request); concatenate all returned names into raw_business_names_list. Respect API rate limits (e.g. short sleep between requests if needed).
    - Model: OpenAI or same as rest of project; no specific model mandated. Use chat completions with one user message containing the prompt + text(s).

  • AI — assign link to business (Step 4.2.1):
    - Input: for each (row, link), you have row["response"] (full text) and the link (text, url). column_names_ordered is the list of allowed column names (focal, competitors, "Unassigned").
    - Rule-first option: if the link text or URL domain clearly matches one business name (e.g. wildsidenaturetours.com → "Wildside Nature Tours"), assign to that column without calling AI. Otherwise use AI.
    - Prompt shape (when using AI): "Given this response text and this link [text](url), which business does this link belong to? Choose exactly one from: [column_names_ordered]. Reply with only that name, or 'Unassigned' if it doesn't belong to any listed business."
    - Output: single string, one of column_names_ordered (including "Unassigned").
    - Batching: can call AI per link or per row (e.g. "for these N links in this response, return N names"). Per-row reduces API calls; per-link is simpler. If rate-limited, add short sleep between requests.
    - Idempotency: same (response, link) → same column; deterministic where possible so re-runs don't flip assignments.
