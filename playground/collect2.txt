COLLECT2 PLAN (HOW_TO_PLAN2 FORMAT)

═══════════════════════════════════════════════════════════════════════════════
PRODUCT INTENT
═══════════════════════════════════════════════════════════════════════════════

Build `full_stack/collect2.py` as a faster, safer collection engine that keeps the same core workflow as `collect.py` while adding multi-model retrieval (ChatGPT, Claude, Perplexity). It is for internal operators running client data collection at scale. The problem it solves is slow single-model collection and inconsistent cross-model coverage.

═══════════════════════════════════════════════════════════════════════════════
HOW IT WORKS
═══════════════════════════════════════════════════════════════════════════════

`collect2.py` accepts a client slug or folder path, resolves the client folder, loads `query_template_bank.csv` and `value_bank.csv`, expands them into questions, and sends each question to selected models through the webish integration layer. It runs calls concurrently with bounded limits, captures per-model success/error per question, and writes a new versioned CSV in the same client folder.

Data flow:
1) input slug/path -> client folder resolution  
2) bank CSV load -> matrix expansion -> ordered question list  
3) concurrent model calls via `call_webish_model(query, model)` wrapper in `full_stack/lib.py`  
4) per-question aggregation (stable original order)  
5) versioned write: `<slug>_aisodataN.csv`

═══════════════════════════════════════════════════════════════════════════════
HOW TO USE / RUN
═══════════════════════════════════════════════════════════════════════════════

Run from repo root:
- `python full_stack/collect2.py <path_or_slug>`
- If `<path_or_slug>` is omitted, prompt interactively (matching current `collect.py` behavior).

Optional flags:
- `--concurrency <int>` (default `6`)
- `--models chatgpt,claude,perplexity` (default all 3)

Environment:
- Keep existing ChatGPT behavior (as webish currently requires).
- Claude and Perplexity keys are required only if those models are selected.
- If a selected model key is missing, do not abort; record model-specific errors.

═══════════════════════════════════════════════════════════════════════════════
CONSIDERATIONS / GOTCHAS
═══════════════════════════════════════════════════════════════════════════════

- Preserve output row order exactly as generated questions.
- Do not overwrite historical aiso files.
- One model failure must not cancel other models or other questions.
- Retries should target transient errors only; final failures go to error cells.
- `collect2.py` must not implement direct provider SDK behavior that bypasses webish prompt/response shaping.
- `collect2.py` must not call `webish(model, query)` directly; it calls one helper: `call_webish_model(query, model)`.
- Add a health guard: if the same model returns an invalid/non-string response 5 times in a row, checkpoint-save current results and stop with a clear fatal error.

═══════════════════════════════════════════════════════════════════════════════
SPECIFICATIONS
═══════════════════════════════════════════════════════════════════════════════

Mandatory files in resolved client folder:
- `query_template_bank.csv`
- `value_bank.csv`

Mandatory output schema (exact order):
1. `question`
2. `response_chatgpt`
3. `error_chatgpt`
4. `response_claude`
5. `error_claude`
6. `response_perplexity`
7. `error_perplexity`

Rules:
- Success for a model -> response column filled, error column empty.
- Failure for a model -> response column empty, error column filled.
- Always emit all schema columns above; if a model is unselected via `--models`, leave that model's response/error cells empty.
- Filename format -> `<slug>_aisodataN.csv` where `N = max(existing)+1` or `0`.

Question-count limiting (match `collect.py` exactly):
- Define module-level constant: `question_number = 50`.
- After building full `questions`, only apply limiting if `len(questions) > question_number`.
- Use the exact same downsampling logic:
  - `q = questions`
  - `questions = []`
  - `n = round(len(q) / question_number)`
  - iterate `i` from `0..len(q)-1`; if `i % n == 0`, append `q[i]` to `questions`
- Print count message equivalent to current behavior (e.g., `only running X questions`).
- If `len(questions) <= question_number`, run all generated questions unchanged.

Model integration contract (lock this):
- `collect2.py` calls: `call_webish_model(query: str, model: str) -> str`.
- `model` accepted values: `chatgpt`, `claude`, `perplexity`.
- `call_webish_model` owns provider/model routing and uses webish-compatible prompt/response shaping.
- `collect2.py` stays provider-agnostic and only handles orchestration, retries, and CSV shaping.

Reliability guard (lock this):
- Valid response type is a non-empty string after trimming whitespace.
- Any non-string or empty-string response is treated as invalid.
- Track consecutive invalid responses per model across the run.
- If a model reaches 5 consecutive invalid responses: write a checkpoint CSV with all completed rows so far, then raise a fatal runtime error and stop the run.
- Fatal error message must include the model name and invalid-streak count.
